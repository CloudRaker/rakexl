# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Rakexl is an opinionated fork of [jexl-extended](https://github.com/konnektr-io/jexl-extended) that extends the [Jexl](https://github.com/TomFrost/Jexl) expression parser with 80+ built-in functions. It provides TypeScript support and optional Monaco Editor integration.

## Commands

```bash
# Install dependencies
pnpm install

# Build (compiles src/ to dist/ using tsconfig.release.json)
pnpm build

# Run tests (Vitest in watch mode)
pnpm test

# Run tests once (CI mode)
pnpm test -- --run

# Run a specific test file
pnpm test -- rakexl.vitest
pnpm test -- filter-test
pnpm test -- completion-provider

# Regenerate all documentation (typedoc → completion docs → build → json → mdx)
pnpm docs
```

## Architecture

### Core Layers

1. **`src/grammar/`** — Pure functions split into category modules: `string.ts`, `math.ts`, `array.ts`, `conversion.ts`, `datetime.ts`, `encoding.ts`, `object.ts`, `utility.ts`. Barrel-exported via `src/grammar/index.ts`. Each function has JSDoc with `@group`, `@example`, `@param`, `@returns` annotations. `src/extended-grammar.ts` is a backward-compat re-export shim (`export * from "./grammar"`).

2. **`src/index.ts`** — The `Rakexl` class extends `Jexl` and registers every grammar function in its constructor as three variants:
   - **Function**: `functionName(arg)` and `$functionName(arg)`
   - **Transform**: `value|functionName`
   - Many functions also have aliases (e.g., `uppercase`/`upper`, `append`/`concat`, `any`/`some`)

   The default export is a singleton: `export default new Rakexl()`

3. **`src/monaco/`** — Optional Monaco Editor integration (peer dependency). Sub-modules:
   - `register-language.ts` — Idempotent language registration, hover provider, folding provider, editor factory (`createJexlEditor`)
   - `monarch-language.ts` — Tokenizer with state machines for syntax highlighting (root, afterPipe, arrayAccess, objectLiteral, strings)
   - `completion-provider.ts` — Context-aware IntelliSense: after `|` shows transforms only; at expression start shows functions/keywords
   - `completion-docs.generated.ts` — Auto-generated from source by `completion-docs.ts` build script
   - `language-configuration.ts` — Bracket matching, auto-closing pairs

### Key Patterns

- Grammar functions do input coercion (e.g., string→number) and return `undefined` on failure rather than throwing.
- The `arrayMap`, `arrayFilter`, `arrayFind`, `arrayReduce`, etc. accept JEXL expression strings as predicates (e.g., `data|filter("value.age > 18")`). These internally create a new Jexl instance to evaluate the sub-expression with `value` and `index` in context.
- Monaco integration uses the language ID `"jexl"` and is guarded by `isJexlLanguageRegistered()` to prevent double-registration.

### Build Output

TypeScript compiles `src/` to `dist/` (CommonJS, ES2019 target). Only `dist/` is published (configured in `package.json` `files` field). The `tsconfig.release.json` excludes tests.

### Tests

Vitest functional tests in `test/`, split by category to match the grammar modules:

| Test file | Tests for |
|-----------|-----------|
| `string.vitest.test.ts` | String functions |
| `math.vitest.test.ts` | Math functions |
| `array.vitest.test.ts` | Array functions |
| `conversion.vitest.test.ts` | Conversion functions |
| `datetime.vitest.test.ts` | DateTime functions |
| `encoding.vitest.test.ts` | Encoding functions |
| `object.vitest.test.ts` | Object functions |
| `utility.vitest.test.ts` | Utility functions |

### Documentation Pipeline

`docs/typedoc.json` is auto-generated by TypeDoc from `src/grammar/index.ts`. The MDX docs in `docs/` are generated by `generate-mdx-docs.ts`. Don't edit auto-generated files directly.

## Adding New Grammar Functions

Follow this strict process when adding or modifying grammar functions.

### 1. TDD — Write Tests First

Before writing any implementation code, add failing tests in `test/`:

1. Create test cases in the matching `test/<category>.vitest.test.ts` file (e.g., `test/string.vitest.test.ts` for a new string function). Create a new file if adding a new category.
2. Tests use `jexl.evalSync(expression, context)` — test the function, `$`-prefixed function, and `|transform` variants.
3. Run `pnpm test -- --run` and confirm the new tests **fail** before proceeding.
4. Only then write the implementation. Run tests again to confirm they **pass**.
5. Never skip the red→green cycle. Do not write implementation and tests simultaneously.

### 2. One File Per Concern

Grammar modules live in `src/grammar/` and are organized by category:

| File | Category | Examples |
|------|----------|----------|
| `string.ts` | String manipulation | `uppercase`, `trim`, `split` |
| `math.ts` | Numeric operations | `sum`, `round`, `sqrt` |
| `array.ts` | Array operations | `arrayMap`, `arrayFilter`, `arraySort` |
| `conversion.ts` | Type conversion | `toNumber`, `toBoolean`, `formatNumber` |
| `datetime.ts` | Date/time | `now`, `dateTimeAdd`, `convertTimeZone` |
| `encoding.ts` | Encoding/decoding | `base64Encode`, `formUrlEncoded` |
| `object.ts` | Object operations | `objectKeys`, `objectMerge` |
| `utility.ts` | General utilities | `length`, `uuid`, `_eval` |

**Rules:**
- Place the new function in the module matching its `@group` JSDoc tag. If no existing module fits, create a new `src/grammar/<category>.ts` and add it to `src/grammar/index.ts`.
- Cross-module imports are fine (e.g., `math.ts` imports `toNumber` from `./conversion`).
- Functions needing the `jexl` instance import it as `import jexl from ".."` (circular at module level, works at runtime).
- Every exported function **must** have JSDoc with `@group`, `@example`, `@param`, and `@returns`.

### 3. Register in `src/index.ts`

After the function is implemented and tested, register it in the `Rakexl` constructor:

```typescript
// FunctionName
this.addFunction("functionName", functionName);
this.addFunction("$functionName", functionName);
this.addTransform("functionName", functionName);
```

Add aliases where they make sense (e.g., `upper` → `uppercase`).

### 4. Monaco Completion Compatibility

The Monaco completion provider reads function metadata from `completion-docs.generated.ts`, which is auto-generated from JSDoc via `completion-docs.ts`. To ensure your new function appears in IntelliSense:

- The `@group` tag determines categorization.
- The `@example` tags become completion documentation.
- The `@param` tags generate parameter snippets.
- After adding the function, run `pnpm docs` to regenerate completion docs.
- If the function is **only** a transform (no function form), it will only appear after `|` in the editor. If it has both forms, it appears in both contexts.

### 5. Checklist

- [ ] Tests written and failing (red)
- [ ] Function implemented in the correct `src/grammar/<category>.ts`
- [ ] Tests passing (green)
- [ ] JSDoc complete (`@group`, `@example`, `@param`, `@returns`)
- [ ] Exported from `src/grammar/index.ts` (via the category module)
- [ ] Registered in `src/index.ts` constructor (function + $function + transform)
- [ ] `pnpm build` succeeds
- [ ] `pnpm docs` succeeds (completion docs regenerated)
